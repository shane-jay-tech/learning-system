## 修法

`pyRun` 的 `execFileSync` 增加显式 `env = { ...process.env, PYTHONIOENCODING: 'utf-8' }`——**强制覆盖**继承值（不只补缺），父进程变量缺失或设错一律归一 utf-8，与 execFileSync 的 `encoding: 'utf8'` 解码口径对齐。python 与 py -3 两通道同享（注入在 pyRun 单点，先例 l922-116/b144 同款）。

## 缺陷复现（本机形态勘误，比锚点更进一步）

- 本机 ACP 已是 UTF-8（`locale.getpreferredencoding()` = utf-8），**「变量缺失」态在本机不复现**（无变量时子进程管道 stdout 也是 utf-8）——锚点 2b 态是标准中文 locale（cp936）机器的形态。
- 用**显式 `PYTHONIOENCODING=gbk` 确定性复现同机制**（修复前）：`FAIL sql-selectall / sql-where SQL 真跑行集一致，FAIL 2 项失败 rc=1`——与锚点 2b 态逐字同形（2 项 SQL 中文行集失败、其余 16 项 ok）。
- 修复后三态全绿：gbk 态 rc=0、缺省态 rc=0、utf-8 态 rc=0（完成标准③：有环境变量时行为不回归——现在连"设错值"也归一，比"不回归"更强）。

## 遗留问题

- pyRun 强制覆盖语义：若未来某候选解释器依赖父进程的自定义 PYTHONIOENCODING（非 utf-8），会被归一——当前题库全 utf-8 口径下是正确行为，记录为设计决定。
- `python -X utf8`（UTF-8 模式）是另一条等价修法（PEP 686 在 3.15 起缺省），env 注入对低版本 Python 更稳，维持现方案。
