# ai_review 反馈缓存键连带面：空代码提交亦走缓存（l1004-32；2218 Q-4 备用档）

> 产线：执行班 l1004-32（2026-10-06）。**备用档零码**；不与 l927-15 并单投递（任务书明令），供 K-1/l927-15 落地时同笔参考。

## §一 现值（三元组行号）

- 键构造两处同款：`core/ai_review.py:62`（写入）与 `:70`（读取）——`key = (lang, pid, sha1(code))`，code 以 **sha1 hex** 入键（非原文，长码不膨胀内存）。
- 空代码实况：`code=""` ⇒ sha1("")＝固定值 `da39…` ⇒ **同题所有空提交共享同一缓存条目**。语义上无害（空码的点评＝同一段固定反馈），但意味着：① 空提交的「点评」被缓存后，学生补写代码前的重复空提交零 LLM 调用（省调用，正向）；② 若空码点评曾被 `_post_check` 改写过，后续真实差异不可达（空码无差异，实际无影响）。
- 缓存守卫已在：`:60` 失败/「暂时不可用」/无 pid **不入缓存**；`_FEEDBACK_CACHE_MAX=64` LRU 上限（:56）。

## §二 键域扩展案（K-1/l927-15 落地时同笔参考）

| 案 | 键形状 | 效果 | 缓存大小影响粗估 |
|---|---|---|---|
| 现状 | `(lang, pid, sha1(code))` | 空码共享一条 | 上限 64 条封顶（LRU），无膨胀面 |
| A 空码短路口径 | `_cached_feedback` 前置 `if not code.strip(): return None`（读侧 1 行）＋写侧同守卫 | 空提交**永不走缓存**（每次离线兜底或真调用）；语义＝空码反馈不值得个性化 | 条目数不增反降（空码条目让位真实码）——LRU 64 内影响 ±1 条级 |
| B 键加 verdict/passed 维度 | `(lang, pid, passed, sha1(code))` | 同码同题不同判读结果不再互相覆盖（现状：先入者赢，通过态覆盖失败态的点评） | 最坏 ×2（同码两态各一条）——64 上限下挤掉约 32 条真实码多样性，**建议上限同步 ×2 至 128** |
| C 不动 | 现状 | — | — |

**材料倾向**：若 K-1（空码短路）落地 ⇒ 自然采用案 A 口径（空码在进 review 前已被拦截，缓存面自动不再触达，两案同笔）；若 K-1 不做而主班在意「通过/失败点评互覆」 ⇒ 案 B 带 128 上限；否则案 C 维持（2218 原判「登记不修」仍成立——现状无泄漏、无膨胀，仅语义洁癖面）。
