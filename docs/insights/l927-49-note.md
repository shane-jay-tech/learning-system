## 二、改法：预检形态，而不是把那一行挪进 try

卷宗「做什么」写的是「把 `pid_key` 取值移入 try（**或预检形态**）」。**选了后者，理由是前者收不住**：
只把 `:192` 那行连同门控挪进 per-item try，记账侧确实安全了，但同一个坏项走到渲染循环
`LANG_META[it["lang"]]` 仍然 KeyError 裸奔 ⇒ 「畸形项不崩」这条判据照样拿不到，
除非把渲染体再包一层 try（那会把渲染期的真异常一起吞成 DEBUG，风险面比收益大）。

预检在两循环**之前**一次筛清，两个循环都只喂筛过的项（`ui/pages/dashboard.py:203-211`）：

```python
        checked = []
        for rank, it in enumerate(plan, 1):
            missing = [k for k in ("lang", "problem_id") if k not in it]
            if missing:
                logger.debug("dashboard: 推荐项缺 %s 键，跳过该项（现有键 %s）",
                             "+".join(missing), sorted(it))
                continue
            checked.append((rank, it))
        for rank, it in checked:          # 记账循环（原 :191）
        for _rank, it in checked:         # 渲染循环（原 :206）
```

- 只挡卷宗点名的那两键（`pid_key` 的取值面）。日志只打**缺哪个键＋该项有哪些键**（键名，不含值），
  不引入新告警形态：按项各记一条 DEBUG、不计数、不汇总、不在面板上提示 ⇒ 与 l924-01 定的那一案同形。
- 预检本身不套 try：`k in it` 对 dict 恒不抛。非 dict 项（`None`／字符串）会在预检处以 TypeError
  裸奔——**与改前同一格同一性质**（改前是 KeyError），属未点名残面，见 §五。

## 四、两处实现选择，都要主班过目

1. **rank 取原序、坏项不重新编号**：幸存四条的 rank 是 `[1,3,4,5]` 而不是 `[1,2,3,4]`。
   理由＝`rank` 被 `_make_rec_id` 编进 rid（`:197`），也在 impressions/payload 里；
   重编号会让同一条推荐在「有坏项的帧」与「无坏项的帧」拿到两个不同 rid，跨帧归因链断裂
   （rid 稳定性是 l927-37 落地 A2 时明确要保的那格）。
   代价＝rank 与卡片视觉序在坏项帧里不等（视觉上第 2 张卡记的是 rank 3）。
   新例里 `[1, 3, 4, 5]` 那一行就是钉这个选择的；要改成紧凑编号，**连同该行一起改**。
2. **预检只挡 `lang`／`problem_id` 两键**，没顺手把渲染体另需的四键（`title`／`topic_title`／
   `difficulty`／`topic_slug`）纳进必填集 ⇒ 缺那四键的畸形项**仍会在渲染循环 KeyError 带走整区**。
   卷宗只点名 `pid_key` 那一格，扩到六键属改判据范围（w42 §B.1）。这一格如实留在此处，未造断言。
