# SM-2 双口径契约登记（l1028-10 · 2026-10-28 · 用户授权批）

> 裁决落点：docs/insights/l927-08-crossrepo-boundary.md §五 X-2 二选一之**「登记为契约」**案
> （用户 2026-10-28 拍板按推荐执行；同案与 2026-06-17 评审 adopt-not-centralize 先例一致）。
> 对案（收敛为单一实现）被否：大改触学习数据、回滚成本高、两仓服务对象不同。

## 契约内容

learning-system 与 kaoyan-system 各自维护一套 SM-2 复习算法实现，**参数口径允许分叉**，
互不视为漂移、互不要求对齐；任何一方不得"顺手统一"另一方的数值或 schema。

| 维度 | learning-system | kaoyan-system |
|---|---|---|
| 实现位置 | `core/progress.py:91-101` | `src/.../schema.ts:427-449` |
| ease 默认 | 2.0 | 2.5（ease_factor） |
| 首间隔 | 3（天） | 1（天） |
| 间隔字段类型 | INTEGER | REAL |
| 服务对象 | 编程刷题（408→437 题，五语言） | 考研备考（SRS 4609 卡） |

## 边界事实（登记时实测）

- 英语功能面整体在 kaoyan 侧，learning 侧零文件重叠（l927-08 §三）。
- 两仓无代码互引、无共享数据表；SM-2 分叉仅是"同名算法、不同参数"，非行为冲突。

## 违约判据（何时须复议本契约）

1. 任一方出现跨仓读取对方 SRS 数据的需求（当前零）；
2. 出现第三套 SM-2 实现（三套即失控，届时收敛案重开）；
3. 学习数据迁移需要两仓口径合一（届时按数据迁移单走，不属本契约）。

满足任一条 → 重开 X-2 裁决，**不得静默改参**。
