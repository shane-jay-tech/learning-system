# 焦点环对比度静态实算（WCAG 1.4.11 / 2.4.11 的 3:1）

> 任务 l924-06 · 班 `qoder-executor-20260924-0955-learn23` · 2026-09-24 · **只读**：零生产码改动、零测试件改动、零浏览器。
> 收口 l923-18 result 的遗留 2「R-1 焦点环对比度仍待浏览器实算」（`zcode-bridge/done/l923-18.result.md:61-62`），
> 正面回答那里的问题：「`rgba(91,91,214,.28)` 描边在深浅背景上是否满足 WCAG 1.4.11 的 3:1，静态判不了」——
> **本班的答案是：判得了，而且结论是确定的不达标。**

## 一、结论

`ui/styles.py` 三组焦点环（:209 / :216 / :225，声明逐字相同）用的都是
**`rgba(91, 91, 214, .28)` 3px solid + outline-offset 2px**，即品牌色 #5B5BD6 的 28% 透明描边。

**实测比值 1.45 – 1.49（假想深底 1.33），门槛 3:1 ⇒ 三组全部不达标，无一例外。**

更要紧的是结构性结论：**这不是"色值差一点"，而是"半透明环与其唯一比较对象同源"导致的先天不可达**——
环画在哪个面上，就要拿合成后的环色跟**那个面**比，α=0.28 时环色只是该面"往 indigo 偏了一点"。
α 扫到 **0.70–0.745** 才刚跨过 3:1（见第四节表），也就是说想靠"调不透明度"救它，
至少要 **2.5 倍**于现值，视觉上就变成一条实心环——那不如直接选一个实色（第六节三档方案）。

对照组：组件本体是合格的（主按钮填充 #5B5BD6 vs 页面 #F5F6FA = **4.97:1**、正文 #172033 vs #F5F6FA = 15.06:1）。
**坏的只有焦点态这一层**，所以目检很容易"看着都挺清楚"而放过——它是"看得见但不够对比"的那一类。

## 二、可复跑取数（两数一体：合成色值 + 对比度）

仓库根 `D:/code/learning-system` 执行，**零依赖、零网络、零写盘**：

```bash
$ python -c "o=lambda f,a,b:tuple(round(a*x+(1-a)*y) for x,y in zip(f,b));L=lambda c:sum(w*(((v/255+0.055)/1.055)**2.4 if v/255>0.03928 else (v/255)/12.92) for w,v in zip((0.2126,0.7152,0.0722),c));R=lambda x,y:(max(L(x),L(y))+0.05)/(min(L(x),L(y))+0.05);F=(91,91,214);print([(('#%02X%02X%02X'%o(F,a,b)),round(R(o(F,a,b),b),2)) for b in [(245,246,250),(255,255,255),(23,32,51)] for a in (0.28,1.0)])"
[('#CACBF0', 1.46), ('#5B5BD6', 4.97), ('#D1D1F4', 1.49), ('#5B5BD6', 5.37), ('#2A3161', 1.33), ('#5B5BD6', 3.03)]
```

三条口径声明（判据要能复算，前提得先写清）：

1. **合成**：CSS source-over 在 **sRGB 编码域**逐通道混合 `C = αF + (1−α)B`（浏览器对 CSS 颜色的默认合成即此口径）。
2. **亮度/对比度**：WCAG 2.x 相对亮度定义（线性化 + 0.2126/0.7152/0.0722 加权）与 `(L1+0.05)/(L2+0.05)`。
3. **相邻色**：`outline-offset: 2px` 使环内外两侧露出的都是**父面**（元素背景不侵入 outline 区），
   故比较对象就是它坐落的那个面——这也是"半透明环先天不可达"的成因。
   ⚠ 敏感性：若改用线性光域合成，绝对值会小幅移动，但 1.4x 对 3.0 的差距远超该口径选择的影响，
   **结论不随口径翻转**。

## 四、为什么"只调不透明度"是条死路（α 扫描）

环色固定 #5B5BD6，只动 α（`*` = 未达 3:1）：

| α | vs #F5F6FA | vs #FFFFFF | vs #172033（假想深底） |
|---|---|---|---|
| 0.20 | 1.31* | 1.32* | 1.21* |
| **0.28（现值）** | **1.46\*** | **1.49\*** | **1.33\*** |
| 0.40 | 1.75* | 1.80* | 1.51* |
| 0.50 | 2.06* | 2.11* | 1.70* |
| 0.60 | 2.42* | 2.50* | 1.90* |
| 0.70 | 2.87* | 3.02 | 2.14* |
| **α_min(3:1)** | **0.73** | **0.70** | **0.995** |
| 1.00 | 4.97 | 5.37 | 3.03 |

两条要点：

1. **streamlit 自带的焦点环也救不了场**。l923-18 的静态普查档（`learn-focus-f1-outline-static-20260923.md:147-148`）
   记下 streamlit 默认 `focusRing = 0 0 0 0.2rem rgba(primary, .5)`。α=0.5 一行的读数是
   **2.06 / 2.11 / 1.70 ⇒ 仍全部不达标**。也就是说：本仓把环换成 .28 的自有描边**没有把它改坏**，
   这类"半透明品牌色环"在 1.4.11 面前本来就不合格——区别只是 .5 比 .28 少差一点。
   所以别指望"退回 streamlit 默认"算合规出路。
2. **深底那一列是唯一能证伪"只要够不透明就行"的**：α=1 的 #5B5BD6 在 #172033 上也只有 **3.03:1**（压线），
   而 α_min = 0.995。⇒ 真要上深色主题，环色必须换成**更亮**的一支（第六节末行）。

补一条静态哨兵是**便宜且不需要浏览器**的（本档已证它是可算问题）。草案三条，口径各守一坑：

1. `L1` 取 `ui/styles.py` 里所有 `outline: …px solid rgba(…)` / `#RRGGBB` 声明（**按规则块取**，
   别按行锚——分组选择器 `a:focus-visible, [role="tab"]…` 跨两行，行锚会漏判成"只有一组"）；
2. 对每条实算它相对**在册浅色 token 全集**（`--bg/--surface/--surface-muted/--primary-soft` ＋ :76 侧栏硬编码）
   的对比度，断言 `min >= 3.0`；
3. **反向自证**：把现值（.28）喂进同一函数，断言它 `< 3`——否则哨兵可能是恒真的空壳。
   （同族教训见纪律档 §廿六⑤：判"零覆盖"与"有覆盖"都要双向。）

这条属**新增判据**、且会让现值当场红（它是真红），排不排由主班定；本单按只读位授权**没动 tests/**。
