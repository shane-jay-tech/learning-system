# 写需求文档（Spec）

给 AI Agent 写 Spec 是"指挥 Agent"的核心技能。写不清楚需求，再强的 Agent 也帮不了你。

## 为什么重要

Agent 不会读心——它只能根据你写的文字来工作。模糊的需求 = 反复返工 = 浪费时间。一份好 Spec 能让 Agent 一次做对，而不是来回五次。

## Spec 三要素

1. **目标**：最终要交付什么（"一个能 XX 的函数/页面/脚本"）
2. **边界条件**：不做什么、限制是什么（"不用数据库"、"兼容 Python 3.8+"）
3. **验收标准**：怎么判断做完了（"输入 X 时输出 Y"、"测试全过"）

## 好 Spec vs 坏 Spec

| 坏 Spec | 好 Spec |
|---------|---------|
| "做个好用的登录功能" | "写一个 Flask 登录接口，POST /login，参数 username+password，成功返回 JWT token，失败返回 401" |
| "帮我分析数据" | "读取 data.csv，按部门分组，计算每个部门的平均薪资和离职率，输出为 summary.csv" |
| "优化一下性能" | "当前列表渲染 1000 条数据耗时 3s，目标降到 500ms 以内，可以用虚拟滚动" |

## 写 Spec 的检查清单

- [ ] 有明确的输入和输出吗？
- [ ] 有边界条件（不做什么）吗？
- [ ] 验收标准可以客观判断吗（不是"好用"、"快"这种主观词）？
- [ ] 技术约束写清楚了吗（语言、框架、版本）？
- [ ] 别人看了能立刻动手吗？

## 常见错误

- 太模糊：用形容词代替具体指标（"快一点" → "响应 < 200ms"）
- 缺验收标准：做完了不知道怎么验证对不对
- 过度设计：一份 Spec 塞了十个需求，应该拆成多个小 Spec
- 假设 Agent 有上下文：Agent 每次对话是独立的，别省略背景
