# 任务拆解

大任务变小任务，是让 Agent 高效工作的关键。拆得好，Agent 每一步都能成功；拆得差，反复返工。

## 为什么重要

Agent 的上下文窗口有限、注意力也有限。一次塞太多要求，它容易遗漏细节。把大任务拆成小步骤，每步清晰可验收，成功率翻倍。

## 拆解原则

1. **单一职责**：每个子任务只做一件事
2. **可独立验收**：做完一步能立刻验证对不对
3. **明确输入输出**：上一步的产出是下一步的输入
4. **粒度合适**：一个子任务 = 一次 Agent 对话能完成的事（通常 < 30 分钟）

## 拆解示例

**原始任务**："做一个员工离职预测系统"

**拆解后**：
1. 数据清洗：读取 CSV → 处理缺失值 → 编码分类变量 → 输出 clean.csv
2. 特征工程：从 clean.csv 提取特征 → 归一化 → 输出 features.csv
3. 模型训练：用 features.csv 训练逻辑回归 → 输出 model.pkl
4. 评估报告：加载 model.pkl → 测试集评估 → 输出准确率+混淆矩阵
5. API 封装：加载 model.pkl → Flask 接口 → POST /predict 返回风险分

## 依赖排序

画出依赖关系：哪些可以并行、哪些必须串行。

```
1. 数据清洗 ──→ 2. 特征工程 ──→ 3. 模型训练 ──→ 4. 评估
                                         └──→ 5. API 封装
```

## 常见错误

- 拆太粗：一步里塞了 3 件事，Agent 容易漏
- 拆太细：每步只有一行代码，管理成本比执行成本还高
- 没标依赖：第 3 步依赖第 2 步的输出，但没说清楚文件名和格式
- 跳步骤：第 1 步没验收就做第 3 步，错误累积到最后才发现

## 做题前检查

1. 这个任务能一步做完吗？（能 → 不用拆）
2. 拆出来的每一步，Agent 能独立完成吗？
3. 每步的验收标准明确吗？
4. 步骤之间的输入输出对得上吗？
